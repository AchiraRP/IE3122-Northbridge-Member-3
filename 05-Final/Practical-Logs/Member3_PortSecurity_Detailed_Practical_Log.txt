NORTHBRIDGE PORT SECURITY – WHY THIS CONFIGURATION WAS CHOSEN
============================================================

This section explains the Northbridge security weakness that led to selecting Port Security for Member 3's plan-linked hardening configuration.

1. NORTHBRIDGE SECURITY WEAKNESS RELEVANT TO PORT SECURITY
------------------------------------------------------------

The Northbridge planning material identifies a physical/network-access weakness around unauthorized device access at branch network equipment. The Port Security planning notes describe the security problem as:

"Unauthorized network-device access resulting from weak physical security at branch network equipment."

In the Northbridge control mapping, Threat 3.2 is associated with Layer 2 Security Hardening (Control 2). The Phase 4 hardening assignment specifically allocates:

Member 3:
- Plan-linked configuration: Port Security
- Threat: 3.2
- Control: 2 (Layer 2 Security Hardening)
- Second practical configuration: Extended ACL – BYOD Network Isolation

2. WHAT VULNERABILITY / WEAKNESS DOES THIS CREATE?
------------------------------------------------------------

The relevant weakness is that an unauthorized device could potentially be connected to a switch access port and attempt to use the network connection intended for a legitimate endpoint.

In a normal unsecured access-port situation:

Legitimate PC
    |
    v
Switch access port
    |
    v
Network

If an unauthorized device is physically able to reach the same access port:

Rogue device
    |
    v
Switch access port
    |
    v
Network

Without an appropriate Layer 2 access control mechanism, the switchport does not by itself enforce that only the intended endpoint's MAC address can use the port.

This is why the practical test used a Rogue-PC: the legitimate PC-BR was disconnected and a different-MAC device was connected to the same protected Fa0/2.

3. WHY PORT SECURITY FITS THIS NORTHBRIDGE WEAKNESS
------------------------------------------------------------

Port Security provides a switch-level control for the access-port problem.

For this practical, the policy was:

- Fa0/2 is an access port.
- Only 1 MAC address is permitted.
- The legitimate PC-BR MAC is learned using sticky MAC learning.
- A different MAC address is treated as a security violation.
- Violation mode is set to shutdown.

Therefore the intended security chain is:

Northbridge weakness:
Unauthorized device can use an access port
        |
        v
Layer 2 access control requirement
        |
        v
Port Security on the access port
        |
        v
Learn legitimate PC-BR MAC
        |
        v
Allow 1 MAC only
        |
        v
Different MAC detected
        |
        v
Security violation
        |
        v
Port enters err-disabled / Secure-shutdown

4. IMPORTANT DISTINCTION: PORT SECURITY VS. OTHER NORTHBRIDGE LAYER 2 RISKS
------------------------------------------------------------

Port Security should not be described as the solution to every Layer 2 threat.

The Northbridge control mapping also associates Layer 2 Security Hardening with Threat 1.1. The planning material discusses ARP spoofing as a separate Layer 2 threat and identifies DHCP Snooping and Dynamic ARP Inspection (DAI) as relevant defenses for that problem.

The distinction is:

- Port Security:
  Controls which MAC address(es) are allowed on a switch access port.

- DHCP Snooping:
  Builds trusted DHCP binding information and helps prevent rogue DHCP-server behavior.

- Dynamic ARP Inspection (DAI):
  Validates ARP traffic using trusted binding information and is used to address ARP-spoofing-related risk.

Therefore, in this Member 3 practical, Port Security is specifically being used for the unauthorized-device/access-port weakness associated with Threat 3.2 / Control 2, as assigned in the Phase 4 configuration plan.

5. NORTHBRIDGE SECURITY OBJECTIVE
------------------------------------------------------------

The objective of this configuration is to reduce the possibility of an unauthorized device using a protected branch switch access port.

The practical evidence demonstrates the objective rather than only describing it:

1. PC-BR was the legitimate endpoint.
2. Its MAC address was learned as a sticky MAC.
3. Only one MAC address was allowed.
4. PC-BR was disconnected.
5. Rogue-PC had a different MAC address.
6. Rogue-PC was connected to the same protected Fa0/2.
7. Traffic from Rogue-PC triggered the Port Security violation.
8. Fa0/2 became err-disabled / Secure-shutdown.
9. The violation counter increased to 1.
10. The legitimate PC-BR was then restored and connectivity was verified.

This gives a direct Northbridge scenario -> vulnerability -> control -> Packet Tracer evidence chain.

============================================================ 5. PORT
SECURITY CONFIGURATION
============================================================

On SW-BR:

configure terminal interface fastEthernet 0/2 switchport mode access
switchport port-security switchport port-security maximum 1 switchport
port-security mac-address sticky switchport port-security violation
shutdown end

What each command does:

switchport mode access Makes Fa0/2 an access port for an endpoint.

switchport port-security Enables Port Security on the interface.

switchport port-security maximum 1 Allows only one secure MAC address.

switchport port-security mac-address sticky Automatically learns the
legitimate MAC and stores it as a sticky secure MAC.

switchport port-security violation shutdown Shuts down the port when an
unauthorized MAC is detected.

The switch returned to Switch# after end and displayed the normal
console configuration message: %SYS-5-CONFIG_I: Configured from console
by console

============================================================ 23. VIVA
QUICK ANSWERS
============================================================

Q: What did you configure?

A: I configured Port Security on SW-BR FastEthernet 0/2, the access port
connected to PC-BR. I enabled Port Security, limited the port to one MAC
address, enabled sticky MAC learning, and configured violation mode as
shutdown.

Q: Why sticky MAC?

A: It lets the switch dynamically learn the legitimate endpoint’s MAC
and retain it as a secure MAC address instead of manually entering the
MAC.

Q: Why maximum 1?

A: The port is intended for one legitimate endpoint, PC-BR. A different
MAC appearing on that port should therefore be treated as unauthorized.

Q: What happens when a rogue device connects?

A: If a different source MAC is detected, the configured shutdown
violation mode causes the port to become err-disabled/Secure-shutdown.

Q: How did you prove it?

A: I disconnected PC-BR, connected Rogue-PC with a different MAC,
generated traffic, and verified Fa0/2 became err-disabled. The Port
Security output showed Secure-shutdown and Security Violation Count = 1.

Q: What were the MAC addresses?

A: Legitimate PC-BR: 0001.C719.40EC

Rogue-PC: 0060.3E3A.A14E

Q: How did you recover the port?

A: I entered shutdown followed by no shutdown on Fa0/2, reconnected
PC-BR, verified Fa0/2 was connected, and successfully pinged the gateway
with 0% packet loss.

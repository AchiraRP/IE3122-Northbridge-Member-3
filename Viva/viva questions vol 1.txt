### Q9. How does DHCP spoofing work?

**Answer:**

> A rogue DHCP server responds to clients and provides malicious network configuration, such as an attacker-controlled default gateway. The attacker can first use DHCP starvation to exhaust the legitimate DHCP server's available addresses, making the rogue server more likely to serve clients.

---

### Q10. What is DHCP starvation?

**Answer:**

> DHCP starvation is an attack where an attacker sends many DHCP requests, commonly using spoofed MAC addresses, to consume the available DHCP address pool.

---

### Q11. Why is a rogue DHCP server dangerous?

**Answer:**

> Because clients may accept the attacker's DHCP response and receive a malicious gateway or DNS configuration. This can allow the attacker to position themselves between the client and legitimate network resources.

---

### Q12. What is the potential impact?

**Answer:**

> The attacker can create a man-in-the-middle position, allowing traffic to be monitored, modified, or disrupted.

```

### Q25. Why did you configure:

```

**Answer:**

### Q26. Why did you use sticky MAC?

```text

```

**Answer:**

> Sticky learning allows the switch to dynamically learn the legitimate device's MAC address and treat it as a secure MAC address instead of requiring me to manually enter the MAC address.

### Q28. What does this command do?

```text

```

**Answer:**

> It configures the switch to shut down the port when a security violation occurs, placing the interface into an err-disabled or secure-shutdown state.

### Q29. Why did you choose shutdown rather than protect or restrict?

**Answer:**

### Q53. Explain this rule:

### Q54. Why are there `0.0.0.255` values?

**Answer:**

> They are wildcard masks. `0.0.0.255` means the first three octets must match while the final octet can vary, so the rule represents the entire `/24` network.

### Q55. Why did you use:

```text

```

**Answer:**

> To allow other IP traffic that is not specifically denied by the preceding rule. The ACL therefore specifically blocks BYOD-to-internal-HO traffic rather than unintentionally blocking all IP traffic.

Your practical log explicitly documents this purpose. Pasted text

# PART 11 — Very Important "Trick" Questions

### Q62. Does your Extended ACL detect malware?

**Answer:**

> No. It does not detect or remove malware. It provides network-level access restriction and supports segmentation. Endpoint protection, monitoring and incident response would still be required.

### Q63. Does Port Security prevent all Layer 2 attacks?

**Answer:**

> No. Port Security specifically controls which MAC addresses can use an access port. Other Layer 2 threats require other controls. For example, DHCP Snooping addresses rogue DHCP-server behavior, while DAI is used against ARP-spoofing-related risk. Pasted text

---

### Q64. Is Extended ACL the same thing as network segmentation?

**Answer:**

> No. VLANs and network architecture provide segmentation, while the Extended ACL enforces communication restrictions between the segments. In my practical, VLAN 50 created the separate BYOD segment and the ACL restricted its access to the internal HO network.

---

### Q65. Can an ACL replace a firewall?

**Answer:**

> No. An ACL provides packet-filtering and access-control functionality, but a dedicated firewall can provide much broader security capabilities depending on the technology, such as stateful inspection and advanced security controls.

---

### Q66. Why didn't you use Port Security to solve Threat 3.1?

**Answer:**

> Because Threat 3.1 is about unauthorized remote access through a shared VPN account. Port Security operates at the switch access-port level and does not address VPN authentication or remote-access identity.

---

### Q67. What would directly address Threat 3.1?

**Answer:**

> Individual VPN accounts, centralized AAA, MFA, proper authorization, and logging/accountability would directly address the shared-VPN credential problem.

---

### Q68. What would directly address DHCP spoofing?

**Answer:**

> DHCP Snooping is the more direct Layer 2 control for rogue DHCP-server behavior. It can identify trusted and untrusted switch ports and build DHCP bindings. Port Security is an additional access-port hardening measure, not a replacement for DHCP Snooping.
